# Compatibility

Streamlit runtime compatibility is pinned to 1.66.1. The historical API matrix comes from the official documentation catalog originally captured under the ignored cache `target/upstream/docs`; its observed docs label is 1.66.0 and its runtime target is 1.66.1. That catalog is a retained evidence scope, not the complete long-term product boundary. Version labels are recorded separately and no inaccessible versioned URL is synthesized.

## Long-term documentation scope

2026-10-27 用户确认长期完整实现目标，并明确功能范围来自官方用户文档，不能从 Python API 导出构造分母。按文档中的功能、子能力、参数行为、配置及使用场景组织工作；Rust 接口和实现可以不同。源码、协议和参考运行只用于核实行为和实现线索。

官方入口包括 [API reference](https://docs.streamlit.io/develop/api-reference)、[开发概念](https://docs.streamlit.io/develop/concepts)和[部署概念](https://docs.streamlit.io/deploy/concepts)。历史目录未覆盖的主题、测试与部署说明也需盘点；每页根据用户可获得的能力归类，不把导航页、概念页或 Python 符号各算成一个待实现接口。托管平台操作与 Rust 应用本身的职责分开判断。

现有矩阵保留各条目的历史证据范围；54 项历史 `not_applicable` 已完成本轮适用性复核，结论见下文，不代表长期目标永久排除该用户能力。缺少 Rust 对应实现不构成不适用理由，已有行为的概念页关联实际功能证据。源码盘点不能给予实现或兼容信用，也不另建 Python API 进度表。

长期 M0 基线已通过独立 Review，当前缺口及后续阶段见 [roadmap](roadmap.md#current-focus)；旧 HTML/catalog 未恢复，新抓取记录来源、实际日期、文档版本及内容身份，不覆盖或冒用旧目录的锁定哈希。当前通过、当前失败、环境受阻和历史结果分别记录，不将 M0 退出作为完整兼容证明。

用户已取消实现源码的 SHA 门禁。旧文档和冻结轨迹中的源码指纹是当时的历史元数据，不再要求当前 Rust、Python 或采集工具源码与其逐字相同。兼容判断依赖固定版本、冻结输入输出和实际功能验证，不因普通实现变化强制重采或归档源码。

各链所记的捕获日期、检查数量和关闭结论描述当时的证据范围；移除源码身份检查后，当前必需检查数量以判定模块和实际重放输出为准，不沿用旧 raw 中的汇总数字。当前工作区验证见 [acceptance](acceptance.md)。

### M0 documentation review

本轮官方文档范围审读保存在 [documentation-scope.json](../compatibility/documentation-scope.json)。它记录用户能力与场景要求、官方 URL、采集时间及内容身份，不记录另一套实现状态。原有 API 页面仍由现有矩阵关联证据；新增审读覆盖过去未登记的概念和部署说明。

新增正文按应用外壳、并发与类型迁移、时区、连接与密钥注入、组件交互及生命周期、富数据、主题与字体、组件打包、应用测试、CI、运行包、Kubernetes/代理/TLS、嵌入等用户能力归并。托管平台账户、面板、分享承诺和 Snowflake 平台操作另作适用性讨论，不直接解释为要重建托管服务。

这是一轮有边界的扩展审读，不代表已穷尽所有参数组合、教程和 FAQ，也不能用分组数或页面数计算功能完成率。未版本化指南保留其实际来源身份，与锁定的 1.66.1 运行语义分开确认。后续实现先写对应使用文档，复用已有冻结参考数据，缺失时补充，再建立 Rust 回归。

The only feature matrix is [compatibility/api-compatibility-matrix.json](../compatibility/api-compatibility-matrix.json). Its captured-page scope is not a claim of completeness: unavailable legacy pages and redirect aliases stay explicit in the matrix and [p0-baseline.json](../compatibility/p0-baseline.json).

Current whole-journey progress, deferred steps and evidence links are tracked in [the journey manifest](../tests/journeys/journeys.json); [acceptance](acceptance.md#remaining-first-release-journeys) retains the requirements and explicit UI preparations. Forms/text input and CSV-app integration are now on mainline. Component reviews and journey results do not independently change the feature matrix or establish complete compatibility.

Each row has an official URL, Rust plan, `implementation_status`, `compatibility_status`, and evidence links. Read the current matrix for evidence-backed progress; source candidates and same-name function counts do not establish implementation or compatibility. Verification must compare Rust API behavior, HTTP/WS/protobuf traces, and the unmodified official frontend against the pinned Python reference.

`python tools/verify_p0.py` regenerates the matrix while preserving prior evidence-backed non-unverified statuses when a row remains the same. New catalog rows and rows without sufficient evidence remain unverified.

## Datetime input (st.datetime_input)

The journey-datetime-v1 chain (2026-10-26) promotes the st.datetime_input row with one measured page (`tests/reference/datetime_app.py`, mirrored by `streamlit/examples/datetime.rs`) across the load stage, with a differential that matched on the first capture. The measured wire: a valued picker carries its ISO "YYYY-MM-DDTHH:MM" default (seconds/microseconds stripped), the ten-year min/max window around the value's DATE (min at 00:00, max at 23:59), the 15-minute default step (bounded [60s, 23h]) and the "YYYY/MM/DD" display format; a None-valued picker carries NO default and anchors its window on today. Its state is `string_array_value` of one ISO datetime (empty array = cleared); the reference's serde also accepts the legacy "YYYY/MM/DD, HH:MM" input spelling, which the Rust codec decodes and re-normalizes. Load-only: this frontend commits datetime values only through its calendar widget (typing never reruns). The committed collector/criterion pair (tests/browser/datetime_capture.py + datetime_contract.py, 7 checks, 6 pytest guards) drove both runtimes with a real Chrome; both published replays return 7/7 exit 0 (python `df95b137...` under tests/reference/reference-browser/datetime/, native `a7e45182...` under tests/browser/rust-datetime/). The None-valued picker's window anchors on the capture day, so the chain was re-frozen whole (probe + both captures) on 2026-10-27; the published frozen bytes are the cross-side evidence.

## Chart libraries (st.altair_chart, st.vega_lite_chart, st.plotly_chart, st.pydeck_chart, st.graphviz_chart, st.mermaid_chart, st.echarts_chart)

The journey-chartlibs-v1 chain (2026-10-26) promotes seven rows with one measured page (`tests/reference/chartlibs_app.py`, mirrored by `streamlit/examples/chartlibs.rs`) that renders all seven surfaces at their defaults. The chart-building libraries (altair, plotly, pydeck, graphviz) are Python-only, so every Rust surface takes the FINAL payload the reference produced — the transformed spec or serialized JSON — and streams it through the element the reference emits. Measured wires: `st.altair_chart` carries the dataset-name indirection spec (caller's keys, then the v5.20.1 schema URL and fit autosize appended; theme streamlit) with the chart's arrow dataset named by the MD5 of its IPC bytes; `st.vega_lite_chart` on the Python side pulls an inline `data.values` list OUT of the spec into the element's arrow data — the Rust side carries the same logical arrow in one content-named dataset referenced by the spec's `data.name` instead (accepted A, 2026-10-28: the top-level form missed same-shape value updates on the official frontend); `st.plotly_chart` carries the figure JSON with config `"{}"` and a 450px default height; `st.pydeck_chart` the deck JSON at 500px; `st.graphviz_chart`'s element id is the reference's calc_hash (BLAKE2b-16, NOT md5) of the delta-path repr with content sizing; `st.mermaid_chart` is a fenced MARKDOWN block (fence one backtick longer than the body's longest run, four minimum; no dedicated element) with stretch width; `st.echarts_chart` uses the reference's COMPACT JSON separators at 350px. The chart datasets ride the reference's pandas-3 IPC: large_string text columns and the pandas metadata (creator stamp replicated from the measured wire). Side-specific normalizations (like $$ID digests): arrow IPC flatbuffers compared LOGICALLY, content-addressed dataset names masked, and pydeck's per-run random layer UUIDs masked. The committed collector/criterion pair (tests/browser/chartlibs_capture.py + chartlibs_contract.py, 7 checks, 6 pytest guards) drove both runtimes with a real Chrome; both published replays return 7/7 exit 0 (python `16b61b16...` under tests/reference/reference-browser/chartlibs/, native re-captured 2026-10-28 under the accepted-A wire `0e013b6e...` under tests/browser/rust-chartlibs/, contract 6/6; the superseded 2026-10-26 native trace described the pre-fix top-level form). ## Data editor interaction semantics (st.data_editor edits round-trip)

The journey-dataeditor-v1 chain (2026-10-27) extends the st.data_editor row past the colconfig load wire: a dynamic-rows editor (`tests/reference/dataeditor_app.py`, mirrored by `streamlit/examples/dataeditor.rs`) driven with real mouse and keyboard through four stages — load, a committed cell edit (canvas click + typing + Enter), one added row (toolbar's Add row button), an edit inside the added row. The glides grid renders on `[data-testid=data-grid-canvas]`; the `glide-cell-*` elements are zero-size ARIA mirrors, so cells are read through mirrors and driven as a user would. Measured semantics both runtimes now match: every rerun sends exactly ONE `string_value` edit state (`{"edited_rows":{"0":{"qty":7}},"added_rows":[{}],"deleted_rows":[]}` — string row keys, column-NAME keys, typed cells; an untouched added row reports `{}`); each run re-emits the editor element with the ORIGINAL table while the written table carries the applied edits — cell edits first, then deletions, then additions with missing cells null — where an int64 column that gains a null upcasts to float64 like pandas (7.0/2.0/NaN) and returns to int64 once the cell is filled, and an untouched text cell stays None (never an empty string). Load-bearing discovery: the reference NEVER streams an add_block for the main container — no published python trace contains one; the official frontend creates the root block on new_session, and Rust's historical leading `main_container` add_block per run was a divergence now removed (it also reset the frontend's editor edit state, which had masqueraded as a "reload storm"). The committed collector/criterion pair (tests/browser/dataeditor_capture.py + dataeditor_contract.py, 7 checks with logical-arrow dataframe comparison, 6 pytest guards reading the published python trace) drove both runtimes with a real Chrome; both published replays return 7/7 exit 0 (python under tests/reference/reference-browser/dataeditor/, native under tests/browser/rust-dataeditor/). Unobserved: row deletion (the pinned frontend exposes no affordance), the fixed/add/delete editing modes, callbacks.

Q5/Q6 补证（2026-10-27）：用户选择仅在结果列出现 null 时放宽 nullable，其他列保留输入标记，原始表不变。既有 Python dataeditor 轨迹的空行 edits 已复用，不重新采集；其输入字段原本可空，不能作为 Python 非空输入的证明。Rust 修前已复现不可空 qty/label 和常见 `RecordBatch::try_from_iter` 输入失败，修后以原四轮 payload 验证原表 FF 及返回表 FF/FF/TT/FT，数值填回后恢复原 dtype/标记。独立 Rust-only 控制补充仅数值为空、填满两列和既有 nullable 标记保留。[Rust 官方前端实测](../tests/browser/rust-dataeditor-nonnullable/README.md)也完成原四步操作，独立读取原始 IPC 核对 schema 与行值。编辑器自身仍发送原始输入，应用收到编辑后的 RecordBatch 后自行展示或处理；相关 rustdoc、指南与测试说明已校正。本次不覆盖其他 Arrow 类型、required/default 列配置、非法单元格或跨会话编辑。

## Custom components v2 (st.components.v2.component)

The journey-componentv2-v1 chain (2026-10-27) promotes the last absent row. In the pinned 1.66.1, `st.components.v2.component(name, html=, css=, js=, isolate_styles=)` takes INLINE trusted strings (not a decorator, not a hosted bundle) and returns a mount callable; mounting streams a `bidi_component` element (Element oneof field 59) carrying the instance's widget id `$$ID-<digest>-<key>` (the reference's fast hash: BLAKE2b-16 over the element type + user key + active-script hash, suffixed with the raw key), the HTML/CSS/JS content strings, EXPLICITLY-EMPTY source paths (the reference assigns even empty strings, so the optional fields ride the wire as ""), the form id, the isolate_styles flag and the JSON data payload with json.dumps default separators, at stretch width and content height. The instance's whole state object registers as ONE `json_value` widget (the reference's BidiComponentSerde: missing default keys filled after frontend state deserialization; the mount returns it), plus an internal `$$STREAMLIT_INTERNAL_KEY_<id>__events` trigger-aggregator widget (`json_trigger_value`) whose callbacks are Python-only and stay unregistered on the Rust side. The Rust surface is `ComponentV2::new(name).html().css().js().isolate_styles()` + `st.component_v2(&component, ComponentMount::new().key().data().default_state())`, mirrored by `streamlit/examples/componentv2.rs` against `tests/reference/componentv2_app.py`. The differential matched on the first capture (DOM testid catalog including `stBidiComponentIsolated`, state markdown `value=hi`, zero exceptions). The committed collector/criterion pair (tests/browser/componentv2_capture.py + componentv2_contract.py, 7 checks, 6 pytest guards) drove both runtimes with a real Chrome; both published replays return 7/7 exit 0 (python `6f5b273f...` under tests/reference/reference-browser/componentv2/, native `71942486...` under tests/browser/rust-componentv2/).

Q3 的局部状态补证（2026-10-27）见 [componentv2-state](../tests/reference/reference-browser/componentv2-state/README.md)：一次 Python 1.66.1 官方前端采集覆盖加载、`value=bye`、普通重跑及显式 null。真实 `json_value` 只有 `value`，返回对象与 keyed session state 均补齐 `untouched=7`。原加载证据未覆盖此边界；Rust 修前真实 WS 复现两者丢字段，修后由内部 codec 在状态提交前补缺失的顶层默认键，既有值与 null 保留。[Rust 回归](../streamlit/tests/runtime/componentv2.rs)直接重放冻结输入和分别保存的两项预期，额外的空 incoming 轮仅证明 Rust 内部保留行为。非法/非对象输入、嵌套合并、多实例及回调副作用不在这组参考证据内。

The journey-componenttrigger-v1 chain (2026-10-27) closes the trigger round-trip that chain left unobserved: the component's JS (an ES module default export receiving `{name, data, key, parentElement, setStateValue, setTriggerValue}`) fires `setTriggerValue("ping", {count})` from a real button click inside the isolated SHADOW ROOT (plain querySelector cannot see the component's HTML — the collector pierces `shadowRoot`), the frontend accumulates the payload on the internal aggregator id it derives itself (`$$STREAMLIT_INTERNAL_KEY_<widget-id>__events`) and the next rerun carries exactly one `json_trigger_value` state whose value is the JSON array string of the fired `{"event", "value"}` payloads; the server-side aggregator registers on EVERY mount unconditionally (its id is derived, never hashed independently), the surfaced value is fresh per run (count=1 then count=2, null before the first fire) and resets after the run like every reference trigger. ## Execution semantics (st.rerun / st.stop)

The pinned Python 1.66.1 reference wire was measured on 2026-10-25 with the [execution_app fixture](../tests/reference/execution_app.py) and a real Chrome CDP probe (ignored round `target/checks/m1-execution-20261025T145710`, four stages: plain, guarded fast `st.rerun`, slow `st.rerun` after a streamed element plus 1.5s sleep, and `st.stop`). The measured contract:

- Every run — client-triggered or server-triggered — opens with `new_session` carrying a fresh `script_run_id` and the same `session_id`, then `session_status_changed(running)`, live-streamed deltas, `script_finished`, `session_status_changed(idle)`.
- `st.rerun()` aborts the run at the call point: the run finishes with `script_finished(status=2, FINISHED_EARLY_FOR_RERUN)` followed by the idle status, and the server immediately starts the next run on the same connection without any client `BackMsg`. Deltas already streamed stay on the wire; in the measured fast case the aborted run streamed its selectbox widget delta while the pre-rerun markdown was dropped by same-tick upstream coalescing — the distinction between already-sent frames and deltas still in the upstream queue. The 2026-10-30 native-WS queryparams/rerun capture additionally retains five synchronous rerun pairs: their unsent first-run deltas are discarded while all URL messages remain. The Rust send loop now discards only queued deltas when rerun is raised, preserving frames sent before an application await. Code after the call does not execute: later element pushes and session-state writes have no effect.
- `st.stop()` stops the run at the call point with `script_finished(status=0, FINISHED_SUCCESSFULLY)`: deltas before the call stay, deltas after never emit, and the finish status equals a normal successful run.
- `st.quit` does not exist in the pinned 1.66.1: the reference probe measured `AttributeError: module 'streamlit' has no attribute 'quit'` rendered as an exception element (type/message/stackTrace/`widthConfig useStretch`), the run still finishing `FINISHED_SUCCESSFULLY`, and the app continuing normally afterwards. The Rust API therefore exposes no `quit`; exception-element rendering today covers the duplicate-key takeover below.

The Rust run-loop, suppression rules, per-run identities and the J04 rerun step follow this contract. `st.rerun()`/`st.stop()` are implemented behind a bounded-ownership run loop in the rerun handler (each iteration re-runs with the registry widget values and no second BackMsg, fresh `script_run_id`, same session), with element pushes and session-state writes suppressed after either call; two real-WS regressions pin the measured statuses and suppression. Real-Chrome captures against the mirrored fixture/example match the reference end states and lifecycle exactly, with three documented differences: each Rust run opens with the pre-existing `main_block` AddBlock delta accepted by all journey evidence so far; the fast rerun case streams the pre-rerun markdown live — identical to the reference slow case, while upstream's same-tick coalescing dropped it; and the Rust lifecycle frames populate `ForwardMsg.hash` (`"script_finished"`, `"session_status_changed"`) where the reference leaves that field empty — a pre-existing Rust ForwardMsg shape, byte-verified against the pinned 1.66.1 protobuf, that the official frontend processes unchanged.
